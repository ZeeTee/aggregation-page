# 📰 手工新闻

把一条新闻链接加入 **AI 日报**(`ai-news-daily`)的手工队列,并查看今天已经加进去的新闻。

线上:https://www.zeetng.cloud/tools/manual-news/

## 这是什么

日报系统每天 08:00 自动抓取新闻源出报。但总有"自动抓不到、你就是想收进去"的新闻 ——
这个工具就是那个入口:给一个链接,它会在**下一次日报**里**保底入选**
(不占常规的 20 条名额,也不会被单类 5 条上限挤掉)。

## 用法

1. 填入新闻链接 → 点「添加到日报」
2. 服务端自动抓取标题与正文(抓不到时可以展开「高级选项」自己填)
3. 在下面的「今天添加的新闻」里确认结果

几个要点:

| 项 | 说明 |
| --- | --- |
| 生效时机 | 并入**下一次**日报(每天 08:00)。08:00 前加 → 当天就有;白天加 → 次日 |
| 去重规则 | **照旧适用** —— 最近日报已收录过的链接会被直接跳过(列表里标为「重复跳过」) |
| 抓不到正文 | 不算失败,条目照样入队,日报里只依据标题/导语摘要 |
| token 成本 | 添加本身**不花 token**(只抓网页),摘要由日报运行时生成 |
| 密钥 | 每次操作都要重新输入,不做任何保存 |

## 状态徽章

| 徽章 | 含义 |
| --- | --- |
| 待用 | 已入队,还没被日报处理 |
| 已并入日报 | 已经进了当天日报(当天的公众号草稿也会带上) |
| 重复跳过 | 与之前日报重复(或本轮已有条目重复),已彻底出局,不会再出现 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/news/manual` | 🔑 读取队列 |
| POST | `/api/news/manual` | 🔑 添加一条(带冷却) |

POST 的响应里**顺带带回刷新后的整个列表**,所以添加完不需要再发一次 GET ——
鉴权接口限流只有 5 次/分钟,一次操作只该消耗一个额度。

## 它是怎么和日报系统打通的

这个工具站(Node/TypeScript)与日报系统(Python)是**两个独立项目**。打通方式:

```
浏览器 → 工具站 /api/news/manual
       → execFile(python3 -m newsdaily.cli.add_news --json …)   ← cwd 在日报项目里
       → 读回一份 JSON
```

**为什么是调它的 CLI,而不是直接读写队列 JSON 文件:**
队列的语义(URL 规范化规则、条目 id 的哈希算法、72h 去重记忆判断、
`included`/`duplicate` 生命周期)全部实现在日报项目的 Python 代码里。
如果在 TS 侧重写一遍,两条实现迟早会漂移 —— 比如 URL 规范化少去掉一个追踪参数,
就会把本该判为"重复"的链接放行。所以这里只做一件事:**调它的 CLI,读回 JSON**,
保证单一实现。为此日报侧的 `add_news` 增加了 `--json` 模式
(stdout 只输出一个 JSON 文档,人类可读信息走 stderr)。

## 安全约束

- 两个接口都要 `X-Api-Key`(密钥只走请求头,不进 URL)
- **不经 shell**:`execFile` + argv 数组,不存在命令拼接
- 可执行文件、模块名、选项名全是常量;用户只能提供**值**
- 选项值一律用 `--opt=value` 单个 argv 传递,**因此值以 `-` 开头也不会被 argparse
  当成新选项**(参数注入防护,有专门的测试用例)
- URL 只接受 `http(s)://`,字段长度上限,剔除控制字符
- 有超时上限;详情只进服务端日志,不回传内部路径

## 配置

`.env`(都有默认值,通常不用改):

```bash
NEWS_PYTHON_BIN=/usr/bin/python3            # python3 绝对路径
NEWS_DAILY_DIR=/root/dshworkspace/ai-news-daily   # 日报项目目录(决定读哪个队列)
NEWS_FETCH_TIMEOUT=5                        # 抓网页超时秒数
NEWS_ADD_COOLDOWN=3                         # 两次成功添加的最小间隔秒数
```

⚠️ `NEWS_FETCH_TIMEOUT` **必须给 `server/api.ts` 的 10 秒单请求超时留足余量**。
实测最坏情况(页面挂住直到超时)= 5.12 秒,是安全的;若往上调到 8 秒以上,
接口层会先返回 504。

## 排障

| 现象 | 原因 / 处理 |
| --- | --- |
| 「密钥不正确」 | 密钥不对(与其他工具共用 `.env` 里的 `TOOLBOX_API_KEY`) |
| 「服务端无法访问新闻队列」 | 看服务端日志:多半是 `NEWS_DAILY_DIR` 配错或 python 不在 |
| 「抓取网页超时」 | 站点慢或被墙。展开「高级选项」自己填标题与导语,再点一次(同链接重复添加=更新) |
| 「添加太频繁」 | 冷却中(`NEWS_ADD_COOLDOWN`),等几秒再试 |
| 列表里没有刚添加的 | 点「刷新」;再看徽章是不是「重复跳过」 |

服务端日志:`journalctl -u aggregation-page -n 50`(添加/跳过都会记一条 `manual news add`)。
